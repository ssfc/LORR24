## Abstract

(Prompt: Generalize abstract of this article in Chinese)

合作路径规划可以抽象为在图中为多个智能体计算不碰撞的路径，连接它们的起始位置和目标位置。本文提出了一种快速算法，可以为一般类别的问题提供完整性保证，而无需对图的拓扑结构做任何假设。具体而言，该方法可以解决任何可解实例，其中图的大小为 n，且最多有 n-2 个智能体。该算法使用了两种基本操作：一种是“推”操作，智能体沿着目标方向移动，直到无法继续前进；另一种是“交换”操作，允许两个智能体交换位置，而不改变其他智能体的配置。本文还提供了在合作路径规划的困难实例上的模拟实验，并与其他方法进行了比较。实验结果显示，所提出的算法在涉及数百个智能体、需要高度协调的问题上表现良好，并且具有良好的可扩展性。

## 1  Introduction

(直接翻译)

协同路径规划需要为图上的多个智能体计算路径，其中智能体必须从它们各自的起始节点移动到它们各自的目标节点，同时避免碰撞。这个问题与许多应用相关，例如仓库管理、智能交通、采矿、太空探索以及计算机游戏。

### 1.1 Background

(Prompt: Generalize Section "1.1 Background" of this article in Chinese)

这个问题可以通过耦合方法解决，该方法为复合图 $ G_n = G \times G \times \dots \times G $ 进行规划，其中 \( G \) 是原始图，\( n \) 是智能体的数量；或者通过解耦方法解决，其中路径分别计算，然后解决冲突。与完整搜索方法（如 A*）结合时，耦合算法能够实现完整性和最优性。然而，耦合规划由于对 \( n \) 的指数级依赖而变得不切实际，很快就会需要过多的时间和内存。

在优先级方案中，路径是依次计算的，高优先级的智能体被低优先级的智能体视为移动障碍物 [Erdmann 和 Lozano-Perez, 1986]。搜索优先级空间可以帮助提高性能 [Bennewitz 等, 2002]。这种解耦规划通常会剪枝那些高优先级智能体允许低优先级智能体前进的状态，这可能会排除唯一的可行解。现代的解耦方法考虑了动态优先级和窗口搜索 [Silver, 2005]，以及用于改进多智能体启发式计算的空间抽象 [Sturtevant 和 Buro, 2006]。另一种现代基于搜索的技术是在网格世界中创建流网络，从而显著减少分支因子和重新规划的次数 [Wang 和 Botea, 2008]。

某些方法旨在在保持完整性的同时减少搜索空间的大小。一种混合技术为每个智能体规划，基于其他智能体的未来路径，但在分配目标和避免死锁时采用耦合方法 [Qutub 等, 1997]。另一种方法手动将大型图分解为预先指定类型的子图 [Ryan, 2007]。然后在子图之间进行规划，再协调每个子图内的运动。对于具有特定拓扑的图，已经存在高效的策略来解决多智能体路径规划问题 [Peasgood 等, 2008]，[Surynek, 2009]。对于网格世界中的特定领域，存在一个完整的多项式时间算法 [Wang 和 Botea, 2009]。最近的一个顺序方法计算了大规模问题的最优解耦，将其分解为完全耦合的子问题 [van den Berg 等, 2009]。

### 1.2 Contribution

(Prompt: Generalize Section "1.2 Contribution" of this article in Chinese)

本文提出了一种新的合作路径规划方法，该方法在计算上高效，并且对于一个非常广泛的问题类别是完整的，即所有在具有 \( n \) 个顶点的图中，最多有 \( n - 2 \) 个智能体的实例。

与传统的耦合 A* 方法相比，所提出的方法在计算速度上快了很多个数量级，因为它将搜索集中在获取解决方案所必需的操作子集上。与现有的提供完整性保证的其他方法相比，所提出的方法为更广泛的问题类别提供了类似的保证。此外，该方法不对底层图的拓扑做任何假设，因为它不要求图是网格（如其他方法所要求的）[Wang 和 Botea, 2008]，[Wang 和 Botea, 2009]，也不要求是树形结构[Peasgood 等, 2008]。与一种旨在以计算高效方式解决问题的解耦算法相比[Silver, 2005]，所提出的解决方案在解决时间上具有竞争力，并且不依赖于参数选择。最重要的是，所提出的方法能够解决比不完整的解耦方法更广泛的问题。

该方法采用了两个基本原语。需要注意的是，对于没有智能体之间耦合的简单实例，可以通过每个智能体沿着其最短路径移动到达目标来解决。所提出方法的两个原语之一，称为“推”（push），与此操作类似。一个智能体强迫其他智能体清理其最短路径，并沿着该路径移动。然而，更复杂的问题至少需要两个智能体交换位置。这个问题通过算法的第二个原语“交换”（swap）来解决。当一个智能体无法通过推进行进时，它必须与沿最短路径紧邻的另一个智能体交换位置。这个操作将两个智能体带入图的某个部分，在那里可以进行交换。这可能迫使图中的其他智能体作出反应，可能是所有智能体。最终，所有智能体必须返回到它们的原始位置，而这两个智能体交换了位置。如果这两个智能体无法执行交换操作，则该问题无法解决。

实验通过将计算时间与优化过的耦合 A* 替代方案以及针对合作路径规划的快速解耦方法 [Silver, 2005] 进行比较，验证了所承诺的优势。比较包括了小规模、困难的合作路径规划实例，其中智能体之间高度耦合，并且每个智能体需要执行多个交换操作。解耦方法无法解决其中的许多问题，而 A* 方法的计算速度比所提出的算法慢几个数量级。实验还包括了大规模的实例，其中数百个智能体被随机放置。耦合 A* 方法在复合图上无法在合理的时间内为这些问题提供解决方案。当解耦方法可用时，它提供了快速的解决方案，但无法解决所有问题。“推-交换”算法以计算高效的方式解决了所有大规模问题。其解决方案的长度与解耦方法的解决方案长度具有竞争力[Silver, 2005]，但解法路径更易于平滑处理。

## 2 Setup and Notation

(Prompt: Generalize Section "2 Setup and Notation" of this article in Chinese)

考虑一个图 $ G(V, E) $ 和 \( n \) 个智能体 \( R \)，其中 $ n \leq |V| - 2 $。一个赋值函数 $ A : [1, n] \to V $ 将所有智能体放置在不同的顶点上：对于任意 $ i, j \in [1, n] $，且 $ i \neq j $，则 $ A[i] \in V $，且 $ A[i] \neq A[j] $。初始赋值记作 $ S $，目标赋值记作 $ T $。一个动作 $ \pi(A_a, A_b) $ 表示两个赋值 $ A_a $ 和 $ A_b $ 之间的变化，其中只有一个智能体在这两个赋值之间的相邻节点之间移动，即存在 $ i \in [1, n] $，且对于所有 $ j \in [1, n] $，当 $ j \neq i $ 时，$ Aa[i] = Ab[i] $，并且 $ (Aa[i], Ab[i]) \in E $，且 $ Aa[j] = Ab[j] $。路径 $ \Pi = \{A_0, \dots, A_k\} $ 是一系列赋值，满足对于路径 $ \Pi $ 中的任意两个连续赋值 $ A_i $ 和 $ A_{i+1} $，存在一个动作 $ \pi(A_i, A_{i+1}) $。合作路径规划的目标是计算一个路径 $ \Pi^* = \{S, \dots, T\} $，这是一个类似的序列，始于 \( S \) 并以 \( T \) 结束。

### Q: 2 Setup and Notation章节的assignment是什么意思？

在论文的“2 Setup and Notation”章节中，assignment 指的是一个函数 A: [1, n] → V，它将 n 个智能体分配到图 G(V, E) 的唯一顶点上。更具体地说，A[i] 表示第 i 个智能体所在的位置（顶点），并且对于所有不同的智能体 i 和 j，A[i] 不等于 A[j]，保证每个顶点最多只有一个智能体。起始状态的赋值用 S 表示，目标状态的赋值用 T 表示。因此，assignment  描述了在任意时刻，所有智能体的状态，即它们在图中的位置。理解 assignment 对理解后续的“push”和“swap”操作至关重要，因为这些操作正是通过修改 assignment 来改变智能体的位置，最终达到目标状态 T。

### Q: 那starting assignment和target assignment又是是什么意思？

在论文的“2 Setup and Notation”章节中，starting assignment (S) 和 target assignment (T) 是两种特殊的 assignment。它们分别表示智能体在路径规划开始和结束时的状态。[T24]({})  更具体地说，S 表示每个智能体初始所在的位置，T 则表示每个智能体最终需要到达的目标位置。[T24]({})  这两个 assignment 都是函数 A: [1, n] → V 的具体实例，其中 A[i]  分别代表第 i 个智能体在 S 和 T 状态下的位置。[T24]({})  算法的目标就是找到一条路径，将智能体从 S 表示的初始状态转换到 T 表示的目标状态。[T25]({})  换句话说，算法需要找到一系列的 assignment，从 S 开始，到 T 结束，并且相邻的 assignment 之间只允许一个智能体移动到其相邻节点。[T25]({})  理解 S 和 T 对理解整个算法至关重要，因为它们定义了问题的起始和目标。

## 3 Push and Swap

(直接翻译)

这一部分提出了一个新颖的、完整的算法来解决合作路径规划问题。

### 3.1 Algorithm

(Prompt: Generalize Section "3.1 Algorithm" of this article in Chinese)

```pseudocode
// G: graph
// R: all agents
// S: start assignment. 
// T: target assignment
Algorithm 1 PUSH AND SWAP(G,R,S,T)
 1: A ← S // A: current assignment.  
 2: Π∗ ← {A} // Π∗: path
 3: U ← ∅ // agents alreay reached goals
 4: for all r ∈ R do
 5: 	while A[r] != T[r] do // if agent has not reached goal
 6:     	if PUSH(Π∗, G, A, T, r, U) == FALSE then // first try push
 7:         	if SWAP(Π∗,G,A,T ,r,U) == FALSE then // then try swap
 8:             	return ∅ (i.e., Failure)
 9: 	U ←U∪A[r]
 10:return Π∗ (i.e., Success)
```

**Push And Swap:**
算法 1 提供了该方法的高层次操作。PUSH AND SWAP 方法将当前赋值 \( A \) 设置为起始赋值 \( S \)（第 1 行），并通过插入起始赋值来启动解路径 $ \Pi^* $（第 2 行）。它还初始化了已经到达目标的智能体集合 \( U \)，该集合初始为空。然后，对于每个智能体 \( r \)（第 4 行），PUSH AND SWAP 首先尝试通过清除其他智能体的路径来将 \( r \) 推到目标位置 \( T[r] \)（第 6 行）。如果推操作失败，则启动交换操作（第 7 行）。如果交换操作也失败，则问题不可解（第 8 行）。如果 \( r \) 尚未到达目标，则算法会继续对 \( r \) 应用推和交换操作（第 5 行）。当 \( r \) 到达 \( T[r] \) 时，它被插入到静态智能体集合 \( U \) 中，静态智能体的位置信息必须被尊重（第 9 行）。最终，算法返回解路径 $ \Pi^* $，该路径通过调用 PUSH 和 SWAP 算法构造。

```pseudocode
// Π∗: path
// G: graph
// A: agents' location snapshot
// T: target
// r: agent id
// U: agents alreay reached goals
Algorithm 2 PUSH(Π∗, G, A, T, r, U)
1: p∗ ← SHORTEST PATH(G, A[r], T[r])  // compute the shortest path from current loc to target loc
2: v ← first vertex in p∗ after A[r]  // next loc in the shortest path
3: while A[r] != T[r] do  // have not reached goal
4:     while ∃v and v is empty on G do // next loc has not been occupied
		// 这个while把agent不断推向target, until collide with other agent
5:         A[r] = v
6:         Π∗ = Π∗ + {A}
7:         v ← next vertex in p∗
8:     if A[r] != T[r] then  // 推走挡路的agent, 推到最近的空顶点
9:         Mark A[r] and U as blocked on G  // 到达goal的agent不要被推走
10:        v_empty ← closest empty vertex to v on G
11:        p ← SHORTEST PATH(G, v, vempty)
12:        if p == ∅ then
13:            return FALSE
14:        Mark A[r] and U as free on G
15:        v′ ← last vertex on p before vempty
16:        v′′ ← v_empty
17:        while v′′ != v do  // 如果push过程波及到其他agent, 也要一并推走
18:            r′ ← agent for which A[r′] = v′
19:            A[r′] = v′′
20:            Π∗ = Π∗ + {A}
21:            v′′ = v′
22:            v′ → previous vertex along p
23: return TRUE
```

**Push 操作：**
PUSH 算法首先计算输入智能体 $ r $ 当前赋值 $ A[r] $ 和目标赋值 $ T[r] $ 之间的最短路径 $ p^* $（第 1 行）。只要 $ r $ 尚未到达 $ T[r] $（第 3 行），并且它仍然能够向 $ T[r] $ 进展而不需要交换（第 12-13 行），该方法将不断迭代。如果路径 $ p^* $ 上的图顶点没有被占用，则 \( r \) 会沿着这些顶点移动，并且相应的中间赋值会被存储在解路径中（第 4-7 行）。此时，如果 \( r \) 已经到达 $ T[r] $，则 \( r \) 的子问题解决（第 8 行）。否则，路径 $ p^* $ 上的下一个顶点 \( v \) 被另一个智能体占据。此时，算法考虑是否可以将这些智能体从 \( r \) 的最短路径 \( p^* \) 上推开，而不改变 \( r \) 或任何已经到达目标的智能体 \( U \) 的位置（第 9-22 行）。PUSH 算法计算占据顶点 \( v \) 的智能体到离 \( v \) 最近的空顶点 $ v_{empty} $ 的最短路径 \( p \)，前提是 \( A[r] \) 和 \( U \) 中的所有顶点都是障碍物（第 9-11 行）。如果找不到路径 \( p \)（第 12-13 行），则智能体 \( r \) 无法将其他智能体推开并且无法进展，必须进行交换。如果找到路径（第 14-22 行），则路径上的所有智能体都会被推进一个顶点，朝着 $ v_{empty} $ 移动，从而清理出顶点 \( v \) 给 \( r \) 占据。然后算法继续基于新的赋值进行推操作。

```pseudocode
Algorithm 3 SWAP(Π∗, G, A, T, r, U)
1: p∗ ← SHORTEST PATH (G, A[r], T[r])
2: first_collide_agent ← agent on first vertex in p∗ after A[r]
3: success = FALSE
4: swap_vertices ← {All vertices of degree ≥ 3 on G}
5: while swap_vertices != ∅ and success == FALSE do
6:     v = swap_vertices.POP()
7:     p ← SHORTEST_PATH(G, A[r], v)
8:     Π ← ∅
9:     if MULTIPUSH(Π, G, A, T, {r, first_collide_agent}, p) == TRUE THEN
10:        IF CLEAR(Π, G, v, A[r], A[first_collide_agent]) == TRUE THEN  // 清空才能给swap操作留下空间
11:            success = TRUE
12: if success == FALSE then
13:     return FALSE
14: Π∗ = Π∗ + Π
15: EXECUTE SWAP(Π∗, G, A[r], A[first_collide_agent])
16: Π = Π.REVERSE (), exchanging paths for r and first_collide_agent
17: Π∗ = Π∗ + Π
18: if T[s] ∈ U then
19:     return RESOLVE(Π∗, G, A, T, r, first_collide_agent)
20: return TRUE
```

**Swap 操作：**
总体而言，SWAP 操作选择与输入智能体 $ r $ 相邻的智能体  agent_first_collide ，并沿着 $ r $ 的最短路径交换它们的位置，保持已经到达目标位置的智能体不变（第 1-2 行）。对于图 $ G $ 中度数大于等于 3 的顶点 \( v \)，算法计算从 $ A[r] $ 到 \( v \) 的最短路径（第 7 行）。然后算法尝试将智能体 $ r $ 和 agent_first_collide 推到 \( v \) 和其相邻的一个节点（第 9 行）。这通过调用 MULTIPUSH 函数来实现，MULTIPUSH 类似于 PUSH，但不同之处在于它可以同时移动一组相邻的智能体，而不是单个智能体。此外，MULTIPUSH 会忽略集合 \( U \)，并能够不加限制地将所有智能体推离指定路径 \( p \)。如果推操作成功，则 $ A[r] $ 等于 \( v \)，且 $ A[s] $ 与 \( v \) 相邻。为了让 \( r \) 和 \( s \) 在 \( v \) 交换位置，\( v \) 的任何两个相邻顶点（不包括被 \( s \) 占据的顶点）必须被清空（第 10 行）。这就是 CLEAR 函数的目标。如果 \( v \) 的两个相邻顶点无法清空，则无法在 \( v \) 交换 \( r \) 和 \( s \) 的位置，必须考虑另一个顶点。如果图中所有度数大于等于 3 的顶点都被考虑过，且 \( r \) 和 \( s \) 无法到达某个顶点 \( v \)，则 SWAP 返回失败（第 13 行）。如果交换操作成功，则 MULTIPUSH 和 CLEAR 计算的动作序列会被添加到全局解中（第 14 行），并执行交换操作（第 15 行）。图 1 显示了交换原语的图示例。

一旦交换操作完成，在 MULTIPUSH 和 CLEAR 操作中计算出的动作序列 $ \Pi $ 必须被反转，以便集合 \( U \) 中的智能体能够在 SWAP 操作结束时返回到它们的目标位置。  

需要注意的是，\( r \) 和 \( agent_first_collide \) 已经交换了位置，因此，在成功反转动作序列时，\( r \) 执行的路径现在需要由 \( s \) 反向执行，反之亦然（第 16 行）。反转后的动作序列随后会被添加到解路径 \( \Pi^* \) 中（第 17 行）。  
最终，可能发生的情况是，智能体 \( s \) 原本属于集合 \( U \)，此时 \( s \) 的赋值需要调整，以确保 \( A[s] = T[s] \)。这一调整通过函数 RESOLVE 完成（第 19 行）。这一步将在本节后续进行讨论。

**Clear 操作：**  

CLEAR 尝试为 SWAP 操作释放度数大于等于 3 的顶点 \( v \) 邻域中的两个顶点。为了简洁起见，这里不提供详细的算法，但描述了大致的操作步骤。  

假设两个相邻的智能体 \( r \) 和 \( s \) 想要交换位置，并且当前分别占据顶点 \( v \) 和 \( v \) 的一个相邻顶点。为了让 \( r \) 和 \( s \) 交换位置，必须释放 \( v \) 邻域中的另外两个顶点。在释放智能体 \( a \) 的过程中，存在三种情况，如图 3 所示：

**情况 1**：  

直接将智能体 \( a \) 推到一个相邻顶点 \( v \) 或它的邻居。如果情况 1 无法释放两个顶点，但在 \( v \) 的邻域中存在一个空闲顶点，则可以采用情况 2。

**情况 2**：  

在情况 2 中，\( r \) 被推向 \( s \)，临时释放顶点 \( v \)，使得智能体 \( a \) 可以通过 \( v \) 移动到它的空闲邻居 \( v' \)。一旦 \( a \) 到达 \( v' \)，它可以尝试再次从 \( v \) 推开，清理邻域。

**情况 3**：  

情况 3 是情况 2 的扩展，其中智能体 \( a \) 尝试通过 \( r \) 和 \( s \) 占据的顶点来清理 \( v \) 的邻域。此情况不需要考虑是否可以在 \( v \) 上执行交换，因为它要求 \( a \) 与 \( r \) 和 \( s \) 交换位置。如果能够在 \( v \) 上交换 \( a \) 与 \( r \) 和 \( s \)，那么必定有另外两个空闲顶点在 \( v \) 邻域中，此时就不需要清理 \( a \) 了。因此，若要让 \( a \) 与 \( r \) 和 \( s \) 在 \( v \) 上交换位置，则必须使用第二个交换顶点 \( \dot{v} \)。然而，如果 \( a \) 能在 \( \dot{v} \) 上与 \( r \) 和 \( s \) 交换，那么 \( r \) 和 \( s \) 也可以在 \( \dot{v} \) 上交换。类似地，也可能是 \( a \) 在 \( v \) 上与 \( r \) 交换，然后在 \( \dot{v} \) 上与 \( s \) 交换。如果在 \( \dot{v} \) 上 \( a \) 与 \( s \) 能交换，\( r \) 和 \( s \) 也能在 \( \dot{v} \) 上交换。由于 SWAP 会检查所有度数大于等于 3 的顶点，因此会检查 \( \dot{v} \)，使得情况 3 无需考虑。

**Resolve 操作：**  

当调用 RESOLVE 时，智能体 \( r \) 与智能体 \( s \) 交换位置，但 \( s \) 已经到达其目标（例如，\( A[s] \in U \)）。为使 \( r \) 继续进展，且 \( s \) 能回到其目标，必须考虑几个情况：

1) 使用 PUSH 将 \( r \) 推向它的路径进一步前进，释放当前顶点，即 \( s \) 的目标。智能体 \( s \) 可以推向它的目标。
2) 如果 \( r \) 的 PUSH 操作失败，则需要与阻碍其最短路径的智能体再次交换。如果交换成功，那么重复步骤 1 的 PUSH 操作。如果失败，则再次交换 \( r \)，重复步骤 2。

有时，\( r \) 可能一直交换到达目标位置。在这种情况下，\( r \) 与目标智能体 \( r' \) 交换了位置，而 \( r' \) 必须继续进行解析过程，以便为 \( s \) 清除目标。如果步骤 2 中的任何交换失败，则解析过程不可行，从而使得最初调用 RESOLVE 的交换操作无效。

### Q: Algorithm 1的第5行是什么意思?

Algorithm 1的第5行代码“`while A[r] ≠ T[r] do`” 的意思是：对于当前正在处理的智能体 r，只要智能体 r 的当前位置 `A[r]` 不等于其目标位置 `T[r]`，就持续执行循环内的操作。[T27]({})  这意味着，算法会反复尝试将智能体 r 推向（push）或与其他智能体交换位置（swap），直到智能体 r 到达其目标位置 `T[r]` 为止。[T27]({})  这体现了算法的核心逻辑：持续迭代地移动智能体，直到所有智能体都到达各自的目标位置。[T27]({})  `A[r]` 代表智能体 r 在当前赋值（assignment）中的位置，而 `T[r]` 则代表智能体 r 的目标位置。[T24]({})  这个循环确保算法不断尝试移动智能体 r 直到它到达目的地。[T27]({})

### Q: Algorithm 2中第9行什么意思?

算法2的第9行代码`Mark A[r] and U as blocked on G` 的意思是：将智能体 r 的当前位置 A[r] 和集合 U 中所有智能体的当前位置在图 G 上标记为阻塞状态.  这里，A[r] 是智能体 r 当前所在顶点，U 是已经到达目标位置的智能体集合.  “标记为阻塞”意味着在后续寻找路径时，这些顶点将被视为障碍物，其他智能体不能占据这些位置.  这是因为，在“推挤”操作中，算法需要确保已经到达目标的智能体（U 集合中的智能体）以及正在进行“推挤”操作的智能体 r 不会被其他智能体移动或挤压.  通过标记这些顶点为阻塞状态，算法可以保证这些智能体的位置在“推挤”过程中保持不变，从而避免冲突。

### Q: Algorithm 2 PUSH( Π∗, G, A, T , r, U)中LINE 17-LINE22是什么意思？

在Algorithm 2的PUSH(Π∗, G, A, T, r, U)中，LINE 17到LINE 22的主要操作描述了如何按照路径`p`将阻挡目标顶点`v`的代理逐步“推开”，以便输入代理`r`能够继续前进。

具体来说：
1. **初始化**：从`vempty`（最近的空顶点）开始，沿路径`p`逆向遍历（`v′′ = vempty`，`v′ = 最靠近vempty的p上的顶点`），即逐步处理路径上的每个顶点，直到回到`v`。[T17]({})

2. **逐步推动**（LINE 18-LINE 22）：
   - 遍历之前已确定路径`p`上的每个顶点，找到当前顶点`v′`上占据的代理`r′`（LINE 18）。
   - 将代理`r′`的当前分配更新为`v′′`，即将代理移动到路径上的下一个顶点`v′′`（LINE 19）。
   - 更新全局路径解`Π∗`，来记录状态变更（LINE 20）。
   - 将当前遍历的顶点设为前一个顶点（`v′′ = v′`），继续处理该路径直到`v′′ = v`（LINE 21, LINE 22）。[T17]({})

该过程的作用在于逐步将路径上的代理向空位`vempty`方向推移，为输入代理`r`腾出`v`，从而使`r`能够占据`v`并继续向其目标前进。[T16]({}) [T17]({})

关键点：这部分逻辑构成了**推动操作的核心**，确保路径上所有相关代理能够有序移动到新位置，同时为输入代理`r`腾出位置。整个操作在全局路径`Π∗`中实时记录，以供后续调整和回溯操作使用。[T17]({}) [AI KNOWLEDGE]({})

### Q: Algorithm 3中line 4, 为什么选择度数大于3的顶点？

在算法3的第4行，选择度数大于等于3的顶点作为交换位置的候选顶点，是因为只有在这种顶点上，交换操作才有可能成功进行 [T42]({}).  算法的交换操作 (SWAP) 旨在让两个智能体 r 和 s 交换位置 [T37]({}),  而这个交换需要在图 G 中找到一个合适的顶点 v [T38]({}).  为了保证交换的可行性，该顶点 v 必须满足以下条件：智能体 r 和 s 可以通过“多智能体推挤”操作 (MULTIPUSH) 移动到 v 及其相邻的顶点 [T38]({}) [T39]({}),  并且 v 的邻域中至少有两个空闲的顶点，以便 r 和 s 可以交换位置 [T40]({}).  只有度数大于等于3的顶点才可能同时满足智能体 r 和 s 移动到 v 及其邻接顶点，以及在 v 的邻域内存在至少两个空闲顶点的条件 [T40]({}) [T48]({}).  如果 v 的度数小于3，那么 v 的邻域顶点数量不足，无法满足交换操作所需的条件 [T48]({}).  因此，算法选择度数大于等于3的顶点作为候选顶点，以提高交换操作成功的概率。[T42]({})

### Q: Algorithm 3中的s可以理解成agent first collide吗？第一个撞上的agent

是的，在 Algorithm 3 中，s 可以理解为 agent r 在前往其目标 T[r] 的最短路径上遇到的第一个碰撞的 agent [T42]({}),  也就是第一个阻挡 agent r 前进的 agent。算法第 2 行代码 `s ← agent on first vertex in p∗ after A[r]`  明确说明了这一点 [T42]({}).  `p∗` 代表 agent r 到达目标 T[r] 的最短路径，算法寻找 `p∗` 中 `A[r]`  (agent r 的当前位置) 后第一个被占据的顶点，而占据该顶点的 agent 就是 s [T42]({}).  因此，s 并不是任何一个随机碰撞的 agent，而是最短路径上遇到的第一个障碍物，它阻碍了 agent r 直接到达目标 [T42]({}).  理解 s 的含义对于理解后续的交换操作 (SWAP) 至关重要，因为交换操作就是为了解决 agent r 和 s 之间的冲突，从而使 agent r 能够继续前进。[T42]({})

### 3.2 Completeness

(Prompt: Generalize Section "3.2 Completeness" of this article in Chinese)

**定理 3.1**  

PUSH 和 SWAP 对于合作路径规划问题是完备的，其中智能体的数量 \( n \) 小于或等于 \( |V| - 2 \)。

以下讨论提供了证明的概要，由于篇幅限制，本概要结合了三个必须提供完备性的关键点：  
1) 如果 SWAP 失败，则问题不可解；  
2) 一旦智能体到达其目标，PUSH 和 SWAP 始终确保该智能体停留在那里；  
3) 如果初始配置是可解的，那么总是存在一条路径让智能体到达目标，无论它是如何被推送的。

---

**引理 3.2**  

一个合作路径规划问题是可解的，当且仅当 SWAP 可以将智能体 \( r \) 和 \( s \) 带到一个度数大于或等于 3 的顶点 \( v \) 并且该顶点周围有两个空闲顶点。

考虑沿 \( r \) 到目标 \( T[r] \) 的最短路径的顶点序列，其中 \( s \) 被放置在 \( r \) 和 \( T[r] \) 之间。为了使问题可解，必须交换 \( r \) 和 \( s \) 在这条顶点序列中的顺序。即使 \( r \) 采取不同的路径到达目标 \( T[r] \)，如果问题可解，\( r \) 和 \( s \) 沿最短路径的顺序也会发生变化。因此，问题可解当且仅当这两个智能体可以交换位置。

SWAP 会遍历所有度数大于或等于 3 的顶点，检查是否可以使用 MULTIPUSH 使相邻智能体 \( r \) 和 \( s \) 到达一个顶点，应用 CLEAR 操作，并执行交换。

使用 MULTIPUSH 导航复合智能体 \( A \)（由 \( r \) 和 \( s \) 组成）到达 \( v \) 时，有两种情况需要考虑：  
- \( A \) 的初始位置位于包含 \( v \) 的图的环中，或者没有这样的环。如果是环中的情况，假设环中至少有一个顶点是空闲的，那么智能体 \( A \) 可以简单地穿过环到达 \( v \)；MULTIPUSH 不排除 \( U \) 中的顶点。  
- 如果 \( A \) 不在包含 \( v \) 的环中，那么可行性变成了一个“装载”问题。如果沿最短路径到达 \( v \) 的智能体数小于或等于这些智能体可到达的空闲顶点数量，那么“装载”问题将成功，从而允许 \( A \) 到达 \( v \)。在这里，“可到达”被定义为所有可以占用的顶点，而不会经过 \( A \) 路径上的顶点。如果这个问题不可解，那么 \( A \) 无法到达 \( v \)。

根据 CLEAR 的构造，算法会尝试释放一个顶点 \( v \) 邻域中的所有相关可能性。因此，如果复合智能体 \( A \) 可以到达的所有度数大于或等于 3 的顶点都被耗尽，并且 CLEAR 在每个顶点上失败，那么就无法交换 \( r \) 和 \( s \) 的位置，从而使得合作路径规划实例不可解。

---

**引理 3.3**  

在应用一次 PUSH 和 SWAP 原语后，至少有一个智能体朝着其目标迈出了进展，并且已经到达目标的智能体将停留在那里。

PUSH 通过构造排除了在集合 \( U \) 中的顶点，在寻找清除特定路径的智能体位置时。如果路径中有顶点在 \( U \) 中，方法会返回失败，表明需要执行 SWAP。  
SWAP 在尝试交换两个相邻智能体的位置时，不会排除图中的任何顶点。当应用 MULTIPUSH 和 CLEAR 尝试将两个智能体带到可以交换的顶点时，可能会干扰到所有已到达目标的智能体。因此，在执行交换后，MULTIPUSH 和 CLEAR 中执行的所有操作会被反转（第 16 行），使得所有已经到达目标的智能体返回到其目标位置。

当智能体 \( a \) 使用 PUSH 沿其路径向前进展时，它不会干扰任何已经到达目标的其他智能体，进展也有助于计算解。然而，如果 \( a \) 被阻塞，那么 PUSH 就无法使其继续前进。此时，智能体 \( a \) 必须与阻挡其路径的智能体交换位置才能继续朝着目标前进。通过 SWAP 的构造，任何已经到达目标的智能体，在交换过程中需要移动时，都将在动作反转过程中返回其目标位置。SWAP 操作结束时，\( a \) 已经沿其最短路径交换位置，朝着目标取得了进展。

---

**引理 3.4**  

如果初始智能体配置是可解的，那么通过 PUSH 和 SWAP 操作到达的任何配置都将保持可解性。

在规划其他智能体时，智能体 \( a' \) 可能会从其初始顶点被推离。由于这种位移，可能看起来没有路径让 \( a' \) 从当前位置到达目标。然而，需要注意的是，智能体 \( a' \) 完全可以通过一系列 PUSH 和 SWAP 操作从其初始顶点到达当前位置，并且可以通过类似的操作返回到其初始顶点。在最坏的情况下，智能体 \( a' \) 将不得不返回其初始顶点，然后沿原始路径到达目标。引理 3.3 显示，PUSH 和 SWAP 操作的一次迭代将使智能体在可解的实例中取得进展。如果初始配置是可解的，那么 \( a' \) 就能够到达其目标。实例的可解性仅取决于初始配置，因为任何通过 PUSH AND SWAP 达到的配置都可以反转。

最后的可扩展性实验集中在需要高度协调的紧密耦合问题上。这类问题通常无法通过传统的解耦技术解决，需要更为集中的方法。这些实验使用了循环链（Loop-Chain）基准问题，并调整了循环的大小，以便可以容纳更多的智能体。在这些基准测试中，所有智能体之间的耦合程度很高，所有智能体必须做出各自的次优选择，以便解决全局问题。图7(c)展示了在这种类型的问题中，随着智能体数量的增加，PUSH AND SWAP方法的计算时间。图中可以看出，即使在这个特别困难的实例中，计算100个智能体的时间仍然是可处理的。而WHCA*方法甚至无法解决这个问题的最小版本，如图4所示（Loop-Chain）。

**解法质量**：虽然使用PUSH AND SWAP时没有质量保证，但在所有实验中直接应用该算法的结果，在较小的基准问题中提供了具有竞争力的质量，并且在随机放置问题中，相较于WHCA\*算法，效果明显更好。表1和表2显示，在基准问题和单次旋转问题中，两种方法计算的总解决方案长度相似。在随机网格环境中，PUSH AND SWAP方法的解决方案要比WHCA*方法短大约20%。图8展示了每种方法计算的平均解决方案长度。通常，PUSH AND SWAP的解法质量取决于为解决问题而必须执行的**交换次数**。在可以自由使用PUSH的环境中，如随机网格，解法质量将显著优于高度受限的问题，如循环链基准问题，在这些问题中，为计算解决方案必须执行许多交换。

### Q: 什么是loop-chain?

Loop-Chain 是论文中使用的一个基准测试问题，用于评估协作路径规划算法的性能 [T78]({}) [T93]({}).  它是一个环形结构，多个智能体被放置在环内，目标是让所有智能体在环上顺时针或逆时针移动一个位置 [T78]({}) [T82]({}) [T93]({}).  这个测试问题的特点是智能体之间高度耦合，要解决全局问题，所有智能体都需要做出局部次优的选择 [T93]({}).  由于这种高度耦合性，传统的解耦方法很难有效地解决 Loop-Chain 问题 [T94]({}).  论文中使用了 Loop-Chain 问题及其不同规模的变体来评估“推挤与交换”算法在大规模、高度耦合问题上的性能 [T93]({}) [T94]({}).  图4中展示了 Loop-Chain 问题的基本结构 [T78]({}).

## 5 Discussion

(Prompt: Generalize Section "5 Discussion" of this article in Chinese)

本文提出了一种计算高效且完整的方法，用于解决具有至少两个空节点的合作路径规划问题。通过结合两种基本操作，该算法能够像一个成熟的解耦规划器一样快速解决广泛的问题，且不依赖于参数选择。与解耦方法不同，所提出的PUSH AND SWAP算法能够解决智能体完全耦合的问题，以及那些智能体可能需要反复偏离目标位置以解决全局问题的问题。

该算法有潜力扩展到解决只有一个空节点的问题，只要图中存在冗余的循环（例如，15-puzzle问题）。这需要对交换操作进行扩展，以利用路径图中的循环，从而保持所有未交换智能体的不变性。

PUSH AND SWAP方法计算的是一个**顺序**解法，并不旨在提供路径质量保证。然而，被推动的智能体始终沿着最短路径朝着目标移动。通过连续调用SWAP函数引入了一些冗余运动。通过更复杂的版本的该函数，可能可以避免这种冗余。一般来说，顺序解法可以在后处理步骤中平滑并并行化，这是一个值得研究的有趣方向。

必须强调的是，合作路径规划中存在不同的路径最优性概念，例如所有智能体路径成本的总和，或与帕累托最优相关的概念，这些都可以用来评估解法的质量。
